Motion Studio / Drill 05

View transitions

Change the page in one step, and let the browser animate the difference. Elements that share a name fly from their old place to their new one.

What this teaches

  • Write the state change, not the animation. document.startViewTransition(update) snapshots the page, runs your plain DOM update, snapshots again, and animates between the two. Your update code stays the same with or without it.
  • A shared view-transition-name is what makes an element travel. Give the old element and the new element the same name and the browser morphs position and size between them. Unnamed content just crossfades.
  • Names must be unique at each snapshot. Name only the element that is about to move, just before the transition, and move the name across inside the update callback. Static names on a whole grid of items collide or animate everything.
  • Snapshots are images. Text that changes size gets stretched unless you scale it by height and give the element a box that hugs its text (width: fit-content).
  • Feature-detect and fall through. No API or reduced motion means the same update runs directly. Move focus yourself either way: to the detail heading on open, back to the plate on close.

The lines that matter

function open(id) {
  const tile = tiles[id];
  name(tile, 'plate');                     // old state: the clicked tile owns the names
  const vt = document.startViewTransition(() => {
    name(tile, '');                        // a name may exist only once per snapshot
    showDetail(id);                        // the ordinary DOM update
    name(detail, 'plate');                 // new state: the detail takes them over
  });
  vt.finished.finally(() => name(detail, ''));
}
// name(el, base): el.shape.style.viewTransitionName = base && base + '-shape', same for title

::view-transition-group(plate-shape) { animation-timing-function: var(--ease-out); }
::view-transition-new(plate-title)   { height: 100%; width: auto; }
