Motion Studio / Drill 03

CSS scroll-driven animations

Swap the clock of an ordinary CSS animation for the scrollbar. No scroll listeners, no library, and it runs off the main thread.

What this teaches

  • A scroll position is a timeline. scroll() follows a scroller from top to bottom; view() follows one element through the scrollport. The @keyframes stay ordinary; only the clock changes.
  • animation-range picks the slice of the trip. Name it by phase (entry, contain, cover, exit) plus a percentage, instead of computing pixel offsets by hand.
  • Name a timeline when the tracked element is not the one that moves. view-timeline: --row on the row lets its small fill bar ride the row's timeline rather than its own 8 px one.
  • Keep the effect on the compositor. Scroll-driven transform and opacity run off the main thread, so they stay smooth while JavaScript is busy. The percentage readout animates a registered custom property, which costs main-thread work; use that trick sparingly.
  • Make the unsupported state the finished state. Everything sits inside @supports (animation-timeline: view()). Older browsers see full content, and a small IntersectionObserver adds the reveals back.

The lines that matter

@keyframes grow {
  from { transform: scaleX(0); } to { transform: scaleX(1); }
}

@supports (animation-timeline: view()) {
  /* reading progress: the root scroller is the clock */
  .reading-bar {
    animation: grow linear both;
    animation-timeline: scroll(root block);
  }
  /* a row publishes its view timeline; its fill subscribes */
  .row { view-timeline: --row block; }
  .row .fill {
    animation: grow linear both;
    animation-timeline: --row;
    animation-range: entry 0% entry 100%;
  }
  /* prose: done rising when 30% of the way through */
  .reveal {
    animation: rise linear both;
    animation-timeline: view();
    animation-range: entry 10% cover 30%;
  }
}

Write animation-timeline after the animation shorthand: the shorthand resets it.
